# 阶段 A 人工测试指南

适用范围：Streamlit 阶段 A 页面。建议用约 15～25 分钟完成本指南，无需 API Key，不会启动文献检索或 PDF 下载。

> 本文件是待执行的人工验收步骤，不代表已经完成真实浏览器验收。

## 1. 启动前后端

以下命令均在项目根目录执行。

首次使用或尚未安装前端依赖时：

```bash
.venv/bin/python -m pip install -e '.[dev,ui]'
```

### 终端 1：后端（推荐使用独立测试数据库）

```bash
PHASE_A_TEST_DIR=$(mktemp -d /tmp/literature-phase-a-manual.XXXXXX)
export LITERATURE_DATABASE_URL="sqlite:///$PHASE_A_TEST_DIR/business.db"
export LITERATURE_CHECKPOINT_DB="$PHASE_A_TEST_DIR/checkpoints.db"
export LITERATURE_PROJECTS_ROOT="$PHASE_A_TEST_DIR/projects"
echo "本次测试数据目录：$PHASE_A_TEST_DIR"
.venv/bin/literature-clarifier --reload
```

请记下输出的测试目录。以上配置将测试数据与现有 `workspace/` 隔离；不需要删除、清空或迁移原数据库。

### 终端 2：前端

```bash
LITERATURE_API_BASE_URL=http://127.0.0.1:8000 .venv/bin/streamlit run frontend/app.py
```

浏览器打开：

- 前端：<http://127.0.0.1:8501>
- 后端健康检查：<http://127.0.0.1:8000/health>
- 后端接口文档：<http://127.0.0.1:8000/docs>

点击前端的“检查后端连接”，预期出现“后端连接正常”。

若使用默认业务数据库进行测试，可直接运行 `.venv/bin/literature-clarifier --reload`，但会在现有数据库中新增测试项目。下面推荐继续使用独立测试数据库。

## 2. 主流程：创建、澄清和错误重试

在“原始研究问题”填写：

```text
大语言模型能否改善高校教师的文献检索效率？
```

点击“创建项目”。预期显示项目 ID、对话记录和当前澄清问题。复制保存项目 ID，后续恢复时会用到。

**按照页面当前问题和目标字段回答，不依赖固定提问顺序。** 此问题通常会询问以下内容：

| 当前目标 | 建议回答 | 核对重点 |
|---|---|---|
| 研究对象 | `高校教师` | 对象保存正确 |
| 核心干预 / 暴露 / 概念 | `大语言模型` | 核心概念保存正确 |
| 关注结果 | `文献检索效率` | 结果为列表 |
| 研究类型 | `不限` | 该字段显示“不限” |
| 起始年份、结束年份 | 先按下面日期错误测试，再回答 `2020—2026` | 时间与语言互不串写 |
| 文献语言 | 先按下面语言错误测试，再回答 `我想检索中文和英文文献` | 规范结果为 `zh`、`en` |

每次点击“提交回答”后，检查新的问题和“结构化研究问题”区域。不要提前点击最终确认。

### 日期错误测试

当询问时间范围时，依次提交：

```text
2026-2020
2025-abc
2025,2026,2027
1499-2026
```

每次预期：

- 出现可理解的年份输入错误。
- 当前问题和轮次保持不变。
- 输入内容保留，日期字段不被错误值覆盖。

然后将回答改为 `2020—2026` 并提交，预期可继续下一轮。

### 语言错误测试

当询问文献语言时，依次提交：

```text
[2025,2026]
中文,abc
```

每次预期：

- 出现要求填写语言的提示。
- 当前问题仍是语言问题，轮次不增加。
- 错误回答仍留在输入框，可以直接修改。
- 语言字段没有年份或 `abc`；已回答的时间仍是 2020～2026。

最后改为：

```text
我想检索中文和英文文献
```

提交后预期进入等待确认的页面。核对摘要、系统假设，以及结构化字段：

```json
{
  "population_or_object": "高校教师",
  "intervention_or_exposure": "大语言模型",
  "outcomes": ["文献检索效率"],
  "date_from": 2020,
  "date_to": 2026,
  "languages": ["zh", "en"]
}
```

“研究类型”应显示“不限”。此时应看到“确认研究问题”和“提交修订”，阶段 A 还没有确认完成。

## 3. 修订与“不限”检查

保持等待确认状态，先测试修订，再最终确认。

### 修订关注结果

1. 在“选择修订字段”选择“关注结果”。
2. “字段边界”选择“设置具体值”。
3. 在修订值中每行填写一项：

   ```text
   检索效率
   检索准确率
   ```

4. 点击“提交修订”。
5. 检查摘要和结构化数据，结果应为 `["检索效率", "检索准确率"]`。
6. 日期、语言和研究对象保持原值；阶段 A 仍未确认。

### 修订语言

1. 选择“文献语言”，保持“设置具体值”。
2. 使用多选组件选择 `zh · 中文` 和 `en · 英文`，点击“提交修订”。
3. 核对语言值为合法代码列表，而不是逗号连接的字符串。

### 日期“不限”后恢复具体值

1. 选择“起始年份”，将“字段边界”切换为“不限”，提交修订。
2. 起始年份应显示“不限”，结束年份仍是 2026，其他字段不变。
3. 再选择“设置具体值”，填写整数 `2020`，提交修订。
4. 起始年份恢复为 2020，旧的“不限”标记应被清除。

“未指定（空值）”表示尚未确定，与明确“不限”不同。清空字段后，后端可能重新要求澄清；如果六轮已用完，也可能按已有轮数上限规则补充默认值和系统假设。因此不要将两种选项视为相同，始终检查提交后的实际状态与假设。

修订不保证一定重新进入澄清态；只要后端返回的状态与页面一致，就应按页面继续。

## 4. 最终确认与恢复

1. 确认摘要、日期、语言和结果符合预期。
2. 点击“确认研究问题”。
3. 页面应显示“阶段 A 已确认”，最终摘要和结构化问题为只读。
4. 不再出现“提交回答”“提交修订”或“确认研究问题”按钮。
5. 页面告知阶段 B 前端将在 P1-02 实现；本次不应启动阶段 B 或看到假跳转按钮。
6. 刷新浏览器，或新开同一前端地址。
7. 在“已有项目 ID”输入保存的 ID，点击“加载项目”。
8. 预期恢复已确认状态，日期、语言、修订后的结果均与确认前一致。

浏览器刷新后可能丢失当前会话；通过项目 ID 恢复是预期行为。项目 ID 必须与创建它的后端数据库配套。

## 5. 单独测试语言否定语义

新建另一个项目，原始研究问题仍使用第 2 节的问题。按照实际提问完成其他字段，到语言问题时回答：

```text
只要中文，不纳入英文文献
```

预期语言为 `["zh"]`，不能是 `["zh", "en"]`。日期仍应保持原先回答的范围。

也可另建项目，直接填写以下完整问题测试初始提取：

```text
对象：高校教师；核心概念：大语言模型；结果：检索效率；系统综述，2020-2026；只要中文，不纳入英文文献
```

预期初始结构化语言为 `["zh"]`。若直接出现等待确认摘要，无需强求它重新询问已经明确的字段。

## 6. 异常与恢复检查（可选）

| 操作 | 预期 |
|---|---|
| 输入不存在的项目 ID，例如 `00000000-0000-0000-0000-000000000000` 并加载 | 提示项目不存在；不清空已经加载的项目 |
| 停止后端后点击“刷新项目状态”或“检查后端连接” | 友好提示无法连接，不显示异常堆栈 |
| 后端停止时提交回答 | 当前项目和待提交的回答保留；后端恢复后可继续 |
| 刷新页面、展开结构化信息或更换修订字段 | 不应自动创建项目、提交回答或确认 |
| 提交时快速重复点击 | 请求处理中按钮禁用；检查对话和轮次未重复推进 |

停止后端使用终端 1 的 `Ctrl+C`。在同一终端重新运行 `.venv/bin/literature-clarifier --reload`，会继续使用此前导出的测试数据库配置。若重开终端，先把第 1 节的三个环境变量指向原测试目录；不要重新生成目录后尝试加载旧项目 ID。

请求超时不一定表示后端未保存，先“刷新项目状态”核对，再决定是否重试。

## 7. 必要时核对原始后端状态

将 `PROJECT_ID` 替换为自己的项目 ID，在浏览器打开：

```text
http://127.0.0.1:8000/projects/PROJECT_ID/state
```

重点检查：

- `status`：最终应为 `confirmed`。
- `question_spec.confirmed`：最终应为 `true`。
- `question_spec.languages`：合法代码，没有年份或垃圾项。
- `date_from/date_to`：没有被语言回答改写。
- `explicitly_unrestricted`：与字段值一致；填回具体值后不再包含该字段。
- `clarification_round`：错误回答前后不变；最多 6 轮。
- `messages`：错误回答不新增记录，成功回答不重复出现。

不要为了测试直接修改数据库。
